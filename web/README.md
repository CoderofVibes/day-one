# web

Kevin's web UI. Design: `docs/UI_DESIGN.md` (the Oct 29 design pass), behaviour: `docs/SPEC.md`.

One shell, four screens, one switch. The bar names the plant and Kevin (an AI assistant); the tabs are **Floor**, **Plants**, **Books** and **HQ**; **Behind the curtain** is a switch that opens the auditor's rail beside the run. Staff screens show dollars, POs, approvals and people; wallets, keys, hashes and gas appear only behind the curtain (`src/run.test.ts` checks every staff line). Colours and type come from `src/tokens.css`: one brand green for Kevin and the primary action, and four status colours that always carry a word (refused, waiting, held, paid). Light and dark follow the system.

- **Floor.** *Up next* is whoever's turn it is with Kevin's one-line ask and their buttons: Ray uploads a batch record (or opens one Kevin already read from the scan folder, listed inside the card with a status pill), Linda's phone shows Kevin's text with YES and NO, Tommy photographs the packing slip, Priya releases or rejects the lot. *The run so far* is the feed, newest first, one card per step with who saw it and a pill for what happened (`statusOf` in `src/run.ts`). The *plant map* sits beside them: flat or 3D (`src/twin`, `src/twin3d`), this run or the recorded group buy, with a one-line caption and a legend.
- **Plants.** Four tiles (needs a person, low stock, mass balance, held in escrow), then what waits on a person (discrepancy reviews, moves to approve, the waste correction), stock by plant filtered to low stock and reviews with a plant filter and a pinned first column, and the mass balance.
- **Books.** Marcy's view: Kevin's line, the price-drift alert, the settled purchase orders, the CSV export and the printable brief; below it the import wizard (`src/ImportPane.tsx`).
- **HQ.** Kevin's limits as the contract enforces them (tiles, category caps, supplier standing), the recorded group purchase, and where the acquirer's ERP view runs.
- **Behind the curtain** (`src/Curtain.tsx`): every account in the run with what it signed and who paid its gas, the contract's ledger line, one card per transaction with the explorer link and the contract's words on a refusal, and the attestation of Kevin's model folded into two chips.

One UI, two sources:

- **Live** (`npm run api`, then open http://localhost:8787/): the screens run the demo behind the HTTP API (`api/`). Each button sends one staff action and the page redraws from the state that comes back; the Plants, Books and HQ screens read the ledger and the contract when opened and whenever the run moves. Replay by default, so each click replays the recorded testnet transaction for that step; `npm run api:live` sends real ones. The API marks the page it serves with a meta tag; that is how the UI knows to run live. Kevin's scan folder (`npm run inbox`) shows up under *Up next* at Ray's turn and folds to one line on anyone else's.
- **Replay** (any static host, `npm run web:build` → `web/dist/`): the Floor steps through the recorded run (`src/data/demo-run.json`, written by `npm run web:data`) with Back/Next, the slider, the arrow keys and Play (2.6 s a step); Plants and Books show the ledger as it stands at the end of the run (`src/data/plants.json`, read-only, with the brief and the CSV in `public/`), HQ says what `npm run escrow` reads. A short guide on first visit says what the page is; `npm run host:build` prepares `dist/` for a public host (docs/HOSTING.md).

The button logic for *Up next* is pure data in `src/live.ts` (`src/live.test.ts`). The video page, `?video=1` (`&view=3d`, `&from=<beat>`), plays the recorded run to the storyboard on a fixed clock with captions (`src/video.ts`, `src/VideoApp.tsx`; docs/RECORDING.md) on the same cards and curtain. In development, `npm run web` proxies `/api` to the API.

Screenshots: `npm run web:shot -- <dir>` (static), `URL=http://localhost:8787/ npm run web:shot -- <dir>` (live, clicks through the run; `PLANTS=1` opens the Plants tab, `FULL=1` captures the whole page), `npm run web:shot:3d -- <dir>` (the twin at the storyboard moments). The live script needs the scan folder empty or confirmed at Ray's turn, since the queue replaces the upload button there.
