# scripts

| Script | Command | What it does |
|---|---|---|
| `setup-testnet.ts` | `npm run setup:testnet` | Creates Acme's testnet accounts (CONTRACTS.md §1). Idempotent. Needs Tony's `acme-holdings.testnet` key in the near-cli-rs keychain; writes new private keys to the git-ignored `.near-credentials/testnet/` and public ids to `config/testnet-accounts.json`. |
| `deploy.ts` | `npm run deploy:testnet` | Builds both contracts in WSL into `contracts/target/near/`, deploys DTUSD ($1,000,000 minted to the treasury) and `spend-policy`, applies the CONTRACTS.md §8 configuration only where the chain differs, registers token storage and funds a 25,000 DTUSD budget when it is empty. Re-running changes nothing. |
| `kevin-mcp.ts` | `npm run mcp` | Kevin as an MCP server on stdio (`agents/kevin/src/mcp.ts`): `get_inventory`, `get_forecast`, `get_mass_balance`, `get_books` over the fictional ledger at the demo's start, `get_policy` read live from the testnet contract with view calls, and `draft_po`, which forecasts, ranks the quotes and writes a draft with its `po_hash`, never signing or submitting. No keys. Each tool answers with Kevin's lines and a JSON copy. Register `npm run --silent mcp` (repo root) as the server command in an MCP client. |
| `reset-testnet.ts` | `npm run reset:testnet` | Dry run by default. With `--yes`: HQ cancels every PO not yet received, withdraws the budget to the treasury, then the spend-policy account deploys an empty wasm and deletes itself (NEAR back to Acme). Its anchors go with it, so run it only right before a re-record; then `setup:testnet` and `deploy:testnet`. `--contract <id>` for a throwaway account under Acme, `--json`. |
| `record-credential-attacks.ts` | `npm run record:credentials` | Attacks 8–11 live on testnet: HQ (keychain) revokes Fennimore's credential, lets Sierra's lapse and credentials Pacific Excipient, whose two deliveries QC rejects (relayed) until the contract suspends it; then Kevin's four POs are refused and Linda's approval changes nothing. Writes `data/attacks/credentials-testnet.json`, which `npm run test:attacks` replays. Once per contract (single-use PO ids, suppliers with no credential yet). |
| `rehearse.ts` | `npm run rehearse` | Before a live recording: runs the relayed half of the demo on a throwaway PO-90xx (refused, Linda's relayed YES, funded retry, Northgate accepts and ships, Tommy's relayed receipt, Priya's relayed QC reject). The reject refunds the escrow, so the budget and spend counters end where they began. |
| `attest.ts` | `npm run attest` | Fetches NEAR AI Cloud's attestation report for Kevin's model (bound to a fresh nonce) and the signature of every recorded answer, verifies all of it including Intel's collateral and NVIDIA's GPU verdict, and writes `data/replay/attestation.json`. Needs `NEARAI_API_KEY`; not billed. |
| `verify-attestation.ts` | `npm run verify:attestation` | Re-verifies that file with no key: quote, nonce and signer binding, measurements, each answer's signature against the hashes in `data/replay/*-llm.json`; Intel and NVIDIA over the network unless `--offline`. Exit 0 when nothing is unverified. |
| `escrow.ts` | `npm run escrow` | Reads the spend-policy contract with view calls only: the budget, the amount in escrow, Kevin's spend this month, every PO with its status, and the policy HQ set (limits, category caps and spend, supplier statuses, roles; `server/src/chain/policy.ts`, the same reader behind `GET /api/policy`). No keys; `--json` for one JSON line. |
| `usdc.ts` | `npm run usdc` | PO-1047 in real Circle testnet USDC (DEMO_SCRIPT step 13): replays `data/usdc/` with no keys. `--setup` creates `spend-policy-usdc.acme-holdings.testnet` and deploys the exact code `spend-policy` runs (read with `view_code`) with Circle's USDC as its token, configures Plant B's slice of CONTRACTS.md §8, adds USDC-only function-call keys for Kevin and the two staff (`<account>.usdc.fc.json`) and funds the order total; `--live --record` runs the order and rewrites the fixture. |
| `demo-group.ts` | `npm run demo:group` | Group purchasing across the three plants (docs/GROUP_BUY.md), replayed from `data/replay/group-chain.json` with no keys. `--sandbox` runs it live on a local NEAR sandbox in WSL, `--live` on testnet once the pool methods are deployed there; `--record` rewrites the fixtures, `--web` the three-plant view's data, `--json` one JSON line. |
| `clean-clone.sh` | `bash scripts/clean-clone.sh` (Linux or WSL) | The clean-clone test: clones HEAD to a fresh folder with no `.env` or `.near-credentials`, runs README steps 1–5 and every keyless command in the README table, prints one PASS or FAIL line per step and exits with the number of failures. Deletes the clone afterwards unless `KEEP=1`. |
| `lib/sandbox.ts`, `lib/dayone-sandbox.ts` | (library) | Starts the `near-sandbox` binary the contract tests download in WSL with the demo's accounts in genesis, and deploys and configures DTUSD and spend-policy on it the way `deploy.ts` does on testnet, plus one purchasing agent per plant. Lets a branch record a run against a changed contract without redeploying testnet. |

`demo.ts` (`npm run demo`, `npm run demo:live`) builds its run from `api/src/env.ts`, the same environment the HTTP API (`npm run api`) uses, so the scripted run and the click-by-click run cannot drift apart.

Spec for the rest (deploy, demo, replay, reset): docs/DEMO_SCRIPT.md.
